## Portal text strategy

The title names the artifact and benefit. The abstract should survive alone: problem insight, implemented workflow, differentiation, selected evidence, practical deployment. The description then explains data semantics, architecture, evaluation, analyst workflow and release direction. There is no evidence that longer text automatically scores better or that a particular opening phrase wins.

Four distinct complete sets are in [submission variants](SIH-SUBMISSION-VARIANTS.md). Prefer the investigator-workflow version as the base. Borrow the ownership-independent insight and one experiment from the other versions. Do not join all four abstracts: that repeats claims and makes the proposal harder to read.

Plain language is useful even for experts: concise, scannable and objective writing improves comprehension in usability studies. The recommendation here is an editorial transfer to SIH, not a measured SIH selection effect. [NN/G concise writing](https://www.nngroup.com/articles/concise-scannable-and-objective-how-to-write-for-the-web/), [plain language for experts](https://www.nngroup.com/articles/plain-language-experts/)

Avoid generic openings about the “rapidly evolving digital landscape”, strings of “innovative/robust/seamless”, unsupported superlatives, rhetorical questions and repeated three-part slogans. State who uses the system, which records it consumes, how the model operates and what the officer can inspect. No detector or style can certify a passage as human-written; the goal is clear, project-specific writing.
